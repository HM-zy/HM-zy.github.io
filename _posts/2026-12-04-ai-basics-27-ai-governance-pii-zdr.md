## 🏢 일상 비유: 외주 인쇄 업체에 서류를 맡길 때

계약서 원본을 외주 업체에 그대로 넘기지 않습니다.

1. **사본을 만들고 민감한 부분을 가립니다** (주민번호·계좌번호 검게 칠하기) → **마스킹**
2. 작업이 끝나면 **원본과 사본을 모두 파기한다는 각서**를 받습니다 → **ZDR(Zero Data Retention)**
3. 그래도 **누가 언제 무엇을 맡겼는지** 기록은 남깁니다 → **감사 로그**

여기서 핵심은 3번입니다. 파기 각서를 받았다고 해서 **우리 사무실 책상 위에 놓인 사본**까지 사라지지는 않습니다. 많은 기업이 이 부분을 놓칩니다.

## 🔄 LLM 요청의 데이터 수명주기 4단계

```text
① 전송         ② 처리          ③ 보관           ④ 학습
우리 앱 → API   모델 추론       제공사 로그      파인튜닝·개선
   │               │               │                │
 마스킹          리전 선택      ZDR 계약         옵트아웃
 최소 전송       캐시 정책      보관 기간        계약 조항
```

각 단계에서 물어야 하는 질문이 다릅니다.

| 단계 | 질문 | 통제 수단 |
|---|---|---|
| ① 전송 | 꼭 필요한 정보만 보내는가 | PII 마스킹, 필드 최소화 |
| ② 처리 | 데이터가 어느 국가 리전에서 처리되는가 | 리전 고정, 서브프로세서 목록 |
| ③ 보관 | 제공사가 얼마나 보관하는가 | ZDR 계약, 보관 기간 명시 |
| ④ 학습 | 우리 데이터로 모델을 학습하는가 | 학습 옵트아웃, 계약 조항 |

**거버넌스는 이 네 칸을 표로 채우는 일**입니다. "ZDR 씁니다"는 3번 한 칸입니다.

## 🧊 ZDR(Zero Data Retention)의 실제 의미

ZDR은 "제공사가 프롬프트와 응답을 **저장하지 않고** 학습에도 쓰지 않는다"는 계약입니다. 하지만 실무에서는 세 가지를 반드시 확인해야 합니다.

| 흔한 오해 | 실제 |
|---|---|
| "아무것도 저장 안 함" | 남용·정책 위반 모니터링을 위한 **단기 보관(예: 최대 30일)** 예외가 있는 경우가 많음 |
| "우리 로그도 안전" | ZDR은 **제공사 쪽** 이야기. 우리 애플리케이션 로그·APM·트레이스에는 원문이 남음 |
| "모든 기능에 적용" | 일부 기능(평가·파인튜닝·배치)은 별도 보관 정책. **기능별로 확인**해야 함 |
| "계약서에 있으니 끝" | 법령상 보관 의무(금융 거래 기록 등)가 있으면 **우리 쪽 보관 정책**이 우선 |

> SA가 고객에게 해야 하는 말은 "ZDR 됩니다"가 아니라 **"제공사 보관 0일, 우리 로그 보관 N일, 삭제 요청 처리 경로는 이것"** 입니다. 세 숫자를 말할 수 있어야 신뢰가 생깁니다.

## 🎭 PII 마스킹: 탐지 → 치환 → 복원

### 1) 탐지
- **정규식**: 주민번호·카드·전화·이메일처럼 **형식이 정해진 것**. 빠르고 무료, 오탐 제어가 쉬움.
- **NER(개인정보 인식 모델)**: 이름·주소·직책처럼 **형식이 없는 것**. 정확도는 높지만 비용·지연이 붙고 오탐이 생김.
- **실무 표준**: 정규식으로 형식 PII를 먼저 걷어내고, NER을 보조로. 둘 다 **탐지 결과를 사람이 검수할 수 있는 큐**를 둡니다.

### 2) 치환
- **비가역 마스킹**: `900101-1******`, `010-****-5432`. 로그·모니터링·분석용. 복원 불가.
- **가역 토큰화**: `[RRN_1]` 같은 토큰으로 바꾸고 **매핑 테이블은 별도 금고**에. 모델이 토큰을 그대로 돌려주면 권한 있는 계층에서 복원. 챗봇처럼 "같은 사람"을 계속 다뤄야 할 때 필요합니다.

### 3) 복원
복원은 **최종 사용자 화면에서만**, 권한 검사를 거쳐서. 절대 로그·트레이스에서 복원하지 않습니다.

### 한국어 함정
한국어는 숫자 뒤에 조사가 붙습니다(`010-9876-5432**로**`). 이때 `\b`(단어 경계)는 **작동하지 않습니다** — 한글도 단어 문자로 취급되기 때문입니다. 그래서 `(?<!\d)…(?!\d)`처럼 **숫자 경계**로 잡아야 합니다. 실제로 이 한 줄 때문에 마스킹이 조용히 0건이 되는 사고가 흔합니다.

## 🏛️ 거버넌스 운영 요소 (문서로 남기는 것)

1. **데이터 분류표**: 고객 데이터·임직원 데이터·계약 정보를 등급으로 나누고, 등급별로 "어떤 모델에 보내도 되는가"를 정합니다.
2. **모델 카드/시스템 카드**: 이 시스템이 무슨 데이터를 쓰고, 어떤 한계가 있는지 한 장으로. 규제 대응(EU AI Act 등)의 기본 산출물입니다.
3. **보관 기간표**: 프롬프트 로그, 응답, 트레이스, 평가 데이터셋 각각의 보관 기간과 파기 주체.
4. **삭제 요청 절차**: 사용자 삭제 요청 → 프로필·요약·벡터 인덱스·백업까지. 25일차 메모리 설계와 직결됩니다.
5. **승인 위원회**: 새 모델·새 데이터 소스 도입 시 누가 승인하는가. 이게 없으면 부서마다 다른 기준으로 확산됩니다.

## 💻 5분 실습: 마스킹은 했는데 로그가 원문이면?

문서 하나에서 PII 4종(주민번호·카드·전화·이메일)을 탐지해 토큰으로 바꾸고, 모델 응답을 복원한 뒤 **"어디까지 마스킹해야 실제로 안전한가"** 를 세 경로로 비교합니다.

```python
import re

PATTERNS = {
    "RRN": r"(?<!\d)\d{6}[- ]?\d{7}(?!\d)",
    "CARD": r"(?<!\d)(?:\d{4}[- ]?){3}\d{4}(?!\d)",
    "PHONE": r"(?<!\d)01[016789][- ]?\d{3,4}[- ]?\d{4}(?!\d)",
    "EMAIL": r"[\w.+-]+@[\w-]+\.[\w.]+",
}

sample = (
    "고객 홍길동(900101-1234567)이 010-9876-5432로 전화했고, "
    "카드 1234-5678-9012-3456으로 12,000원 결제를 요청했습니다. "
    "회신은 hong.gd@example.com 으로 부탁드립니다."
)


def mask(text, vault):
    """형식 PII를 토큰으로 치환하고, 복원용 매핑은 vault(금고)에만 남긴다."""
    masked = text
    for label, pattern in PATTERNS.items():
        def repl(m, label=label):
            token = f"[{label}_{len(vault) + 1}]"
            vault[token] = m.group(0)
            return token
        masked = re.sub(pattern, repl, masked)
    return masked


def restore(text, vault):
    """복원은 사용자 화면 직전에서만. 로그에는 절대 쓰지 않는다."""
    for token, original in vault.items():
        text = text.replace(token, original)
    return text


def leaks(text):
    return {label: len(re.findall(p, text)) for label, p in PATTERNS.items()}


vault = {}
masked = mask(sample, vault)

print("원문 PII:", leaks(sample))
print("모델에 보낸 문장:", masked)
print("전송 후 PII:", leaks(masked))
print("금고에 보관된 토큰:", list(vault))

# 모델은 토큰을 그대로 돌려준다
answer = "결제 요청 접수했습니다. [RRN_1] 고객에게 [PHONE_3]로 안내했고, 영수증은 [EMAIL_4]로 발송했습니다."
restored = restore(answer, vault)
expected = ("결제 요청 접수했습니다. 900101-1234567 고객에게 010-9876-5432로 안내했고, "
            "영수증은 hong.gd@example.com로 발송했습니다.")
print()
print("모델 응답:", answer)
print("화면 표시:", restored)
print("원문 완전 복원:", restored == expected)

print()
rows = [
    ("원문 전송 + 원문 로그", sample, sample),
    ("마스킹 전송 + 원문 로그", masked, sample),
    ("마스킹 전송 + 마스킹 로그", masked, masked),
]
print(f"{'경로':<24}{'모델이 본 PII':>12}{'로그 PII':>10}")
for name, sent, logged in rows:
    print(f"{name:<24}{sum(leaks(sent).values()):>12}{sum(leaks(logged).values()):>10}")

REQ_PER_DAY = 50_000
print()
print(f"하루 {REQ_PER_DAY:,}건이면 1년 로그에 PII {REQ_PER_DAY * 365 * 4:,}건")
```

**실행 결과**

```text
원문 PII: {'RRN': 1, 'CARD': 1, 'PHONE': 1, 'EMAIL': 1}
모델에 보낸 문장: 고객 홍길동([RRN_1])이 [PHONE_3]로 전화했고, 카드 [CARD_2]으로 12,000원 결제를 요청했습니다. 회신은 [EMAIL_4] 으로 부탁드립니다.
전송 후 PII: {'RRN': 0, 'CARD': 0, 'PHONE': 0, 'EMAIL': 0}
금고에 보관된 토큰: ['[RRN_1]', '[CARD_2]', '[PHONE_3]', '[EMAIL_4]']

모델 응답: 결제 요청 접수했습니다. [RRN_1] 고객에게 [PHONE_3]로 안내했고, 영수증은 [EMAIL_4]로 발송했습니다.
화면 표시: 결제 요청 접수했습니다. 900101-1234567 고객에게 010-9876-5432로 안내했고, 영수증은 hong.gd@example.com로 발송했습니다.
원문 완전 복원: True

경로                         모델이 본 PII    로그 PII
원문 전송 + 원문 로그                      4         4
마스킹 전송 + 원문 로그                     0         4
마스킹 전송 + 마스킹 로그                    0         0
```

**체감 포인트**: 두 번째 줄을 보세요. **모델에는 PII가 0건**인데 로그에는 **4건이 그대로** 남습니다. ZDR 계약을 맺어도 이 로그가 남아 있으면, 유출 사고는 제공사가 아니라 **우리 로그 저장소에서** 납니다.

숫자로 보면 하루 5만 건이면 1년에 **7,300만 건의 PII**가 로그에 쌓입니다. 이걸 "삭제 요청이 오면 찾아서 지우자"는 불가능합니다. 그래서 마스킹은 **전송 시점이 아니라 수집 시점**에 해야 합니다.

그리고 `leaks()`의 첫 출력처럼 이 코드가 PII를 4건 모두 잡는 것도 우연이 아닙니다. 처음에 `\b`로 패턴을 썼다면 **전화번호와 카드번호가 0건**으로 나왔을 겁니다(한글 조사가 붙어 단어 경계가 깨짐). 마스킹은 **"0건이 나오면 일단 의심"** 하는 태도가 필요합니다.

## ⚠️ 자주 하는 실수 3가지

1. **마스킹은 했는데 원문을 로그·트레이스에 남김**: 오늘 실습의 두 번째 줄이 정확히 이 사고입니다. 마스킹 지점을 **애플리케이션 경계(수집 지점)** 로 올려야 합니다.
2. **준식별자 조합 무시**: 이름·생년월일·부서를 각각 지워도, 셋을 조합하면 개인을 특정할 수 있습니다. "PII를 지웠다"가 아니라 **재식별 위험 평가**가 필요합니다.
3. **프롬프트 예시에 실제 고객 데이터 사용**: 데모를 만들 때 실제 상담 로그를 few-shot 예시로 붙이는 순간, 그 데이터가 **모든 요청에 실려** 나갑니다. 예시는 반드시 **합성 데이터**로.
