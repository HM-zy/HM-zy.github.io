*"코딩은 잘 끝났는데, 이걸 C-Level 임원들에게 어떻게 보고하고 예산을 따내야 할까요?"*

솔루션즈 아키텍트(SA)의 가장 중요한 역할은 **기술을 비즈니스 가치로 번역하는 것**입니다. 임원은 파이썬 라이브러리 버전이나 임베딩 차원 수에 관심이 없습니다. 

*"이걸 도입하면 우리 직원들의 업무 시간이 얼마나 줄고, 보안 위험은 어떻게 막았는가?"*를 단 1페이지로 설득하는 **아키텍처 의사결정 기록(ADR)과 PoV 제안서 작성법**을 정리합니다.

---

## 📄 임원용 1페이지 제안서의 5대 필수 구성 요소

1. **고객 문제 정의 (Pain Point)**
   - 현황: 사내 매뉴얼이 20여 개 시스템에 분산되어 신입 직원 온보딩 시 규정 탐색에 1일 평균 45분 소모.
2. **기대 효과 및 정량적 ROI (Impact)**
   - 검색 소요 시간 단축: 45분 → 30초 (98% 단축).
   - 문의 건수 감소: 인사·총무팀 반복 규정 문의 40% 자동화.
3. **아키텍처 선택 이유 (ADR: Trade-offs)**
   - 왜 순수 벡터 검색이 아닌 하이브리드(BM25)인가? → 전문 용어 오인식률을 85%에서 95%로 개선하기 위함.
   - 왜 오픈소스 로컬 모델 대신 Claude API인가? → 엔터프라이즈급 긴 컨텍스트 처리 및 PII 개인정보 비학습 보장.
4. **보안 및 규제 방어책 (Risk Mitigation)**
   - 직급별 RBAC 메타데이터 사전 필터링으로 기밀 문서 접근 원천 차단.
   - 읽기 전용(Read-only) 격리 계정 사용.
5. **다음 단계 파일럿 계획 (Next Steps)**
   - 1단계: 인사팀 30명 대상 2주간 베타 테스트 및 추가 질문셋 50개 검증.

## 💻 5분 실습: 1-Page ADR 템플릿 마크다운 구조

```markdown
# [ADR-001] 사내 지식 검색 시스템을 위한 하이브리드 RAG 도입

## 1. 배경 및 비즈니스 문제
- 분산된 사규 매뉴얼로 인한 업무 생산성 저하 (월 1,200건의 단순 문의 발생)

## 2. 검토한 기술 대안
- 대안 A: 관계형 DB 키워드 검색 (장점: 저비용 / 단점: 구어체 질문 인식 불가)
- 대안 B: 순수 벡터 검색 (장점: 의미 파악 우수 / 단점: 사규 조항 번호 검색 실패)
- 대안 C: **하이브리드 검색 (BM25 + Vector) [채택]**

## 3. 최종 결정 및 근거
- 20개 기준 질문셋 테스트 결과, 하이브리드 검색 채택 시 답변 적중률이 75% -> 95%로 대폭 상승하여 대안 C를 최종 채택함.

## 4. 보안 및 비용 영향
- 직급별 메타데이터 필터링 적용으로 열람 권한 격리 완결
- 캐싱 적용으로 예상 월 API 비용 $50 미만 유지
```
