_비용과 편익을 저울에 올려 투자 회수 기간과 KPI로 판정하는 비즈니스 케이스_

14일차에서 **PoV 보고서(ADR)의 형식**을 배웠다면, 오늘은 그 보고서의 빈칸에 들어갈 **숫자**를 만듭니다. 기술 검증은 "잘 된다"로 끝나지 않고, **"그래서 무엇이 얼마나 좋아지는가"** 로 번역되어야 계약이 됩니다.

---

## 🏠 일상 비유: 리모델링 견적서

주방 리모델링을 결정할 때 무엇을 보나요?

- **자재비만 보면** 싸 보입니다. 그런데 인건비·철거비·전기 승압비·유지보수가 붙으면 두 배가 됩니다. (TCO)
- 그리고 "예쁘다"는 성공 기준이 아닙니다. **"조리 동선이 3분 줄었다"** 가 기준입니다. (KPI)

AI 프로젝트도 똑같습니다. **토큰 단가표는 자재비**이고, 진짜 견적은 **구축 인건비·운영 인력·데이터 정제·보안 검토**까지 포함해야 합니다. 그리고 "정확도 87%"는 "예쁘다"와 같은 말입니다.

---

## 🪜 성공 기준은 3단 사다리로

| 층 | 지표 예시 | 누가 보나 |
|---|---|---|
| **기술 KPI** | 골든셋 정답률, 인용 정확도, p95 지연 3초 이내 | 개발·SA |
| **운영 KPI** | 주간 활성률, 질의 재사용률, 에스컬레이션 비율, 답변 피드백 | 운영·PM |
| **비즈니스 KPI** | 건당 처리 시간, 상담 티켓 수, 신규 계약 준비 기간 | 임원·재무 |

**규칙**: 비즈니스 KPI는 **PoV 시작 전에 baseline을 측정**해야 합니다. PoV가 끝난 뒤에 "원래 몇 분이었죠?"를 물으면, 그 숫자는 이미 정치적 협상 대상이 됩니다.

> PoV 계약서에 들어가야 하는 5가지: ① 측정 대상 업무 ② baseline 수치 ③ 측정 기간 ④ 판정 기준(예: 정답률 85% + 채택률 40%) ⑤ **중단 조건(kill criteria)**. ⑤가 없으면 PoV는 끝나지 않고 슬그머니 확장됩니다.

## 🧾 TCO 7항목 — 토큰은 3분의 1이 안 된다

| 항목 | 성격 | 자주 빠지는 것 |
|---|---|---|
| ① 토큰·API 사용료 | 변동비 | 재시도·평가·임베딩 비용 누락 |
| ② 인프라 | 고정비 | 벡터 DB, 앱 호스팅, **관측성 도구** |
| ③ 초기 구축 인건비 | 일회성 | 요구사항·통합·테스트 기간 |
| ④ 운영 인력 | 고정비 | 프롬프트 개선·장애 대응 FTE |
| ⑤ 보안·컴플라이언스 | 일회성+ | 보안 검토, 감사 대응, ZDR 계약 협의 |
| ⑥ 통합·변경관리 | 일회성 | 기존 시스템 연동, 권한 체계 정비 |
| ⑦ 데이터 정제·평가셋 | **가장 큼** | 문서 정리, 골든셋 구축(11일차) |

실무에서 가장 많이 틀리는 항목은 ⑦입니다. 사내 문서가 스캔 PDF·표·중복본으로 뒤엉켜 있으면, **정제에 구축 기간의 절반**이 들어갑니다. 견적에서 이걸 빼면 첫 달에 일정이 무너집니다.

## 📈 ROI 계산식 (그리고 반드시 붙여야 할 민감도)

```text
월 운영비 = 토큰 + 인프라 + 운영 인건비
월 편익   = 월 질의 수 × 실제 사용률 × 건당 절감 시간 × 인건비 × 인정률
투자 회수 = 초기 구축비 ÷ (월 편익 − 월 운영비)
3년 ROI   = (3년 편익 − 3년 TCO) ÷ 3년 TCO
```

여기서 **인정률(capture rate)** 이라는 단어가 낯설 것입니다. "절감한 3분이 정말 생산성으로 이어졌나"를 재무가 인정해 주는 비율입니다. 100%로 잡으면 회수 기간이 절반으로 줄어 보이지만, 그 숫자는 첫 임원 회의에서 바로 반박됩니다. **보수적으로 잡고 민감도를 함께 제시**하는 편이 통과율이 높습니다.

## 💻 5분 실습: 300명 사내 RAG의 TCO·ROI·회수 기간

300명 대상 사내 RAG를 가정하고 **월 운영비·초기 구축비·투자 회수 기간·3년 ROI**를 계산합니다. 마지막에 **채택률 × 인정률 민감도 표**를 출력해, 가정이 틀렸을 때 회수 기간이 어떻게 흔들리는지 봅니다.

```python
USERS = 300                      # 대상 인원
ACTIVE_RATE = 0.6                # 월간 활성 비율
QUERIES_PER_DAY = 6              # 1인 하루 질의 수
WORKDAYS = 22

IN_TOK, OUT_TOK = 4_000, 600     # 질의 1건당 입력·출력 토큰
PRICE_IN, PRICE_OUT = 3.0 / 1_000_000, 15.0 / 1_000_000

INFRA = {"vector_db": 300, "app": 150, "observability": 80}   # 월 달러
OPS_FTE, FTE_COST = 0.2, 7_000                                # 운영 인력
BUILD_MONTHS, BUILD_HEADCOUNT, HEADCOUNT_COST = 6, 3, 10_000  # 초기 구축

MINUTES_SAVED = 3.0              # 질의 1건당 절감 시간(분)
USEFUL_RATE = 0.7                # 답변이 실제 업무에 쓰인 비율
CAPTURE_RATE = 0.6               # 절감 시간 중 생산성으로 인정하는 비율
HOURLY = 28.0                    # 인건비(시간당, 달러)


def monthly(active_rate=ACTIVE_RATE, capture_rate=CAPTURE_RATE):
    queries = int(USERS * active_rate * QUERIES_PER_DAY * WORKDAYS)
    token_cost = queries * (IN_TOK * PRICE_IN + OUT_TOK * PRICE_OUT)
    run = token_cost + sum(INFRA.values()) + OPS_FTE * FTE_COST
    hours = queries * USEFUL_RATE * MINUTES_SAVED / 60
    benefit = hours * HOURLY * capture_rate
    return queries, token_cost, run, hours, benefit


queries, token_cost, run_month, hours, benefit = monthly()
one_time = BUILD_MONTHS * BUILD_HEADCOUNT * HEADCOUNT_COST
net = benefit - run_month
payback = one_time / net
tco3 = one_time + run_month * 36
roi3 = (benefit * 36 - tco3) / tco3

print(f"월 질의 {queries:,}건 | 토큰 ${token_cost:,.0f} + 인프라 ${sum(INFRA.values())} "
      f"+ 운영 ${OPS_FTE * FTE_COST:,.0f} = 월 ${run_month:,.0f}")
print(f"초기 구축 ${one_time:,} | 월 절감 {hours:,.0f}시간 → 월 편익 ${benefit:,.0f} (순 ${net:,.0f})")
print(f"투자 회수 {payback:.1f}개월 | 3년 TCO ${tco3:,.0f} | 3년 ROI {roi3 * 100:.0f}%")

print()
print("민감도 — 채택률(행) × 인정률(열)에 따른 회수 기간(개월)")
print(f"{'':>8}" + "".join(f"{c:>9.0%}" for c in (0.3, 0.45, 0.6)))
for active in (0.4, 0.6, 0.8):
    q, _, run, _, _ = monthly(active_rate=active)
    row = f"{active:>8.0%}"
    for cap in (0.3, 0.45, 0.6):
        h = q * USEFUL_RATE * MINUTES_SAVED / 60
        b = h * HOURLY * cap
        gap = b - run
        row += f"{(one_time / gap if gap > 0 else float('inf')):>9.0f}"
    print(row)
```

**실행 결과**

```text
월 질의 23,760건 | 토큰 $499 + 인프라 $530 + 운영 $1,400 = 월 $2,429
초기 구축 $180,000 | 월 절감 832시간 → 월 편익 $13,971 (순 $11,542)
투자 회수 15.6개월 | 3년 TCO $267,443 | 3년 ROI 88%

민감도 — 채택률(행) × 인정률(열)에 따른 회수 기간(개월)
              30%      45%      60%
     40%       75       38       26
     60%       40       22       16
     80%       27       16       11
```

**체감 포인트**: 토큰 비용은 월 **499달러**입니다. 전체 운영비 2,429달러의 **20%** 에 불과합니다. 나머지는 인프라(530)와 **사람(1,400)** 입니다. "토큰 단가가 내려가면 좋아진다"는 말이 왜 견적을 바꾸지 못하는지 여기서 보입니다.

두 번째로 볼 것은 민감도 표입니다. 채택률 40%·인정률 30%면 회수 **75개월**(사실상 실패), 채택률 80%·인정률 60%면 **11개월**입니다. 같은 기술, 같은 비용인데 **회수 기간이 7배** 차이 납니다. 그래서 PoV에서 봐야 할 것은 정확도만이 아니라 **채택률**입니다.

이 표가 임원 회의에서 강한 이유는, **우리가 좋은 숫자만 고르지 않았다는 것**을 보여주기 때문입니다. "최선 11개월, 최악 75개월, 현실적 목표 16개월"이라고 말하는 SA의 견적은 반박하기 어렵습니다.

## ⚠️ 자주 하는 실수 3가지

1. **절감 시간을 100% 인정**: "질의당 3분 아끼면 3분 전부 생산성"은 재무가 절대 인정하지 않습니다. 실제 업무에 쓰인 비율(USEFUL)과 인정률(CAPTURE)을 곱해 **보수적으로** 잡으세요.
2. **baseline 없이 PoV 시작**: "지금보다 빨라질 것"은 측정이 아닙니다. PoV 전에 **현재 처리 시간·티켓 수를 실측**해 두고, 같은 조건으로 재측정해야 합니다.
3. **모델 단가 인하를 편익으로 계산**: 단가가 내려가면 비용이 줄 뿐, **편익은 그대로**입니다. 편익은 항상 **업무 지표**에서 나와야 합니다.
