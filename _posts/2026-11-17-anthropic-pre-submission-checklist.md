## 2. RAG·Evals GitHub Push (`feat/rag-eval`, `90b7806`)

### 왜 안 올라갔나

커밋은 이미 끝나 있었습니다 — `90b7806`, 브랜치 `feat/rag-eval`, working tree clean. 코드에 키나 비밀값이 없는 것도 확인했습니다.

실패한 곳은 **push 단계 한 곳**입니다. 그 컴퓨터에 GitHub 로그인 정보가 없었습니다. HTTPS에 저장된 로그인도, SSH 키도 없었습니다.

### 터미널에서 PAT로 push

```bash
cd <RAG 프로젝트 폴더>
git status                      # feat/rag-eval, working tree clean 확인
git push -u origin feat/rag-eval
# Username: HM-zy
# Password: GitHub 비밀번호가 아니라 Personal Access Token
```

- **발급 위치**: GitHub → Settings → Developer settings → Personal access tokens
- **권한**: `repo` 체크
- 한 번 push하면 **macOS 키체인에 저장**돼서 다음부터는 묻지 않습니다.
- **토큰은 채팅에 붙여넣지 말고 터미널에만** 입력합니다.

### 올라가는 것 / 올라가지 않는 것

| 구분 | 내용 |
|---|---|
| 올라감 | `rag/`(파이프라인·검색·가드레일·코퍼스 빌더), `evals/`(골든셋, v0~v2 결과, `run_eval.py`), `tests/`, `README` |
| 제외 | `rag/corpus/*.md` — Red Hat 공식 문서 원문, 이력서 파일 (`.gitignore` 대상) |

원문을 올리지 않는 이유는 저작권과 사내 문서 취급 때문입니다. 시험지(`evals/`)와 코드는 올라가도, 교재 원문은 내 컴퓨터에만 둡니다.

### 올라간 상태 확인 (11-17 23:5x 기준)

원격에 `feat/rag-eval` 브랜치가 올라와 있고 head는 `ddf4578`(11-17 23:41)입니다. 내용도 위 목록과 일치합니다 — `rag/`, `evals/golden.jsonl`, `evals/results`, `evals/run_eval.py`, `tests/test_rag.py`, `README.md`가 있고 `rag/corpus`는 없습니다. 즉 **push는 이제 완료된 상태**이고, 남은 건 "이 커밋 구성이 내가 설명할 수 있는 최종본인가"를 확인하는 일입니다.

## 3. Claude for Work 정리 & 면접 대비

### 뭐냐면

claude.ai의 **기업용 요금제(Team, Enterprise)** 입니다. 개인이 아니라 **회사 단위로 Claude를 쓰는 상품**입니다.

### 개인 플랜과 다른 점

- 멤버와 결제를 관리하는 **관리자 콘솔**
- 팀이 같이 쓰는 **Projects** (공유 문서와 지침)
- Google Drive 같은 사내 도구 연결(**커넥터**)
- **더 높은 사용량 한도**
- **Enterprise**는 여기에 SSO, 감사 로그, 더 강한 데이터 통제가 추가됩니다

### 고객 앞에서 제일 중요한 포인트

**비즈니스 대화 데이터는 기본적으로 모델 학습에 쓰이지 않습니다.** 한국 기업 보안팀이 가장 먼저 묻는 질문입니다. "그럼 우리 영업 데이터로 모델을 학습시키는 거 아닙니까?"에 이 한 줄로 답이 됩니다.

### 써 보는 방법

claude.ai → 프로필 → 업그레이드 → **Team**. 최소 좌석 수가 있어서 개인이 써 보려면 돈이 듭니다. **현재 가격과 최소 인원은 확인하지 못했으니** `claude.com/pricing`에서 먼저 확인하세요.

### 면접 대비로는 이게 더 효과적

1. **개인 계정에서 Projects 기능을 직접 써 보세요.** Team과 거의 같은 방식입니다. 써 봤으면 면접에서 "Claude Projects를 써 봤다(used Claude Projects)"라고 정직하게 말할 수 있습니다.
2. **한국 기업이 셋 중 무엇을 골라야 하는지**, **데이터 위치 · 보안 심사 · 운영 주체** 기준으로 설명할 수 있게 준비하세요.

| 선택지 | 데이터 위치 | 보안 심사 | 운영 주체 |
|---|---|---|---|
| **Claude for Work** (claude.ai) | 앤트로픽 SaaS | 앤트로픽 정책·계약 확인 | 앤트로픽 |
| **API 직접 사용** | 내 서비스·내 인프라로 옮기는 설계 | 내 시스템 기준으로 직접 | 우리 팀 |
| **클라우드 경유** (Bedrock, Vertex) | 이미 쓰는 클라우드 리전 안 | 기존 클라우드 계약·심사 절차 그대로 | 클라우드 + 우리 팀 |

정리하면 — **바로 써야 하면 Claude for Work, 제품에 붙여야 하면 API, 데이터가 이미 클라우드에 있고 보안 심사를 그대로 태워야 하면 Bedrock/Vertex** 입니다. 이 한 줄이 면접 답변의 뼈대입니다.

### 이력서에는 실제로 쓴 것만

Team·Enterprise는 **실제로 써 본 뒤에만** 이력서에 넣습니다. Projects를 써 봤다면 "Claude Projects 활용"까지는 정직하게 쓸 수 있습니다.
